# Provenance — lib-q-k12/tests/data/k12_kt{128,256}_vectors.json

Both files' `expected` values were transcribed (into this crate's own JSON schema, not vendored as
raw bytes) from published reference vectors, not generated by lib-q-k12's own code under test.
Because the JSON encoding is this repo's own, byte-for-byte upstream comparison is not possible;
what was verified is that individual vector VALUES match a published reference. Hence `origin =
"third-party"`, not `"upstream"` (no citable upstream URL pins the exact bytes of this JSON file).

- `k12_kt128_vectors.json`: the first (empty-input, 32-byte and 64-byte output) vectors were spot-
  checked byte-for-byte on 2026-08-09 against `github.com/XKCP/XKCP` `tests/TestVectors/
  KangarooTwelve.txt` (fetched live) and match exactly:
  `1ac2d450fc3b4205d19da7bfca1b37513c0803577ac7167f06fe2ce1f0ef39e...` for the 32-byte case. The
  remaining 10 vectors in the file were NOT individually re-verified this session.
- `k12_kt256_vectors.json`: self-declares "RFC 9861 (KangarooTwelve / TurboSHAKE) — test vectors as
  in Appendix A.5"; not independently re-verified against a live RFC 9861 fetch this session.

- `k12_kt256_vectors.json`: origin=third-party; values claimed transcribed from RFC 9861 Appendix A.5 KT256 vectors; not independently re-verified against a live fetch this session

# Reviewed classical-cryptography dependencies
# ============================================
# Enforced by scripts/security_check_classical_crypto.py (run via scripts/security-check.sh).
#
# Format:  <crate dir> | <dependency> | JUSTIFIED|TODO | <reason>
#
# JUSTIFIED  the dependency is required by a specification or by byte-exact vector
#            reproduction, and removing it would mean not implementing the thing.
# TODO       accepted for now but NOT justified. Reported as a warning on every run.
#            A TODO is a debt, not a decision.
#
# Adding a line is the reviewable act. Do not add one to make the gate quiet -- the point
# of the gate is that new classical crypto gets looked at. Removing a dependency means
# removing its line too: an entry matching nothing FAILS as stale, because an allowlist
# nobody prunes silently re-permits the dependency later.
#
# The workspace root's [workspace.dependencies] is deliberately not listed. It pins
# versions for members that opt in with `workspace = true`; the opt-in is what grants use,
# and it happens on the member's own manifest, which is where these lines live.

# --- Standardised parameter sets that are defined over classical primitives --------------
# lib-Q ships no SHA-2 at all, not even for the FIPS 205 SLH-DSA-SHA2 parameter sets or for
# test-vector checksums: only the SHAKE parameter sets are implemented.
#
# MAYO expands its public matrices with AES-128-CTR (zero IV, big-endian block counter),
# matching aes128ctr.c in the reference implementation. Substituting a PQ primitive would
# produce a different, non-interoperable scheme.
lib-q-mayo | aes | JUSTIFIED | MAYO public matrix expansion per spec / aes128ctr.c (src/expand.rs)

# --- NIST KAT harnesses, which are defined in terms of an AES-CTR-DRBG -------------------
# Reproducing published vectors byte for byte means running the DRBG the vectors were
# generated with. These are seeded deterministically for tests, never used as a live CSPRNG.
lib-q-cb-kem | aes | JUSTIFIED | NIST SP 800-90A CTR_DRBG (AES-256, no df) for KAT reproduction (src/nist_aes_rng.rs)
lib-q-hqc    | aes | JUSTIFIED | NIST SP 800-90A AES-256-CTR-DRBG, optional, for KAT reproduction (src/aes_ctr_drbg.rs)
lib-q-random | aes | JUSTIFIED | optional AES-256-CTR-DRBG used for deterministic KAT seeding (src/entropy.rs)

# --- Test-only: comparing against upstream / reference vectors ---------------------------
# dev-dependencies do not ship to users.
lib-q-slh-dsa            | aes  | JUSTIFIED | dev-only; KAT harness DRBG

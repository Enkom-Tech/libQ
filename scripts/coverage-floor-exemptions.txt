# Published crates with no coverage floor
# =======================================
# Enforced by scripts/ci_guard_coverage_floors.py.
#
# Format:  <crate> | <reason>
#
# This file is a RECORD OF A GAP, not a set of approvals. Every line is a published crate
# that no workflow measures against a coverage threshold -- so its coverage can go to zero
# without any CI run noticing. Baseline taken 2026-08-08: 77 published crates, 46 gated
# names, 31 unmeasured.
#
# The guard exists to stop that number growing silently. A newly published crate fails
# until someone puts it in a *_CRATES list or writes a line here; a line for a crate that
# has since been gated also fails, so this file cannot drift out of date.
#
# Removing a line -- by gating the crate -- is the point. Adding one should feel like debt.
#
# Why not simply gate all 31: the per-crate coverage step already runs ~65 minutes for 18
# crates under debug tarpaulin. Tripling that has its own cost, and for the heavy lattice
# crates coverage.yml already records that instrumented keygen is impractically slow. That
# is a CI-budget decision, made deliberately, not by a script edit.
